# Work Planner Discord Bot

A Discord bot for tracking and managing work items with progress tracking. Each team member can manage their own work items and update progress.

## Setup

### Prerequisites
- Node.js v18 or higher
- PostgreSQL database (e.g., Supabase)
- Discord bot token and app ID

### Installation

1. Clone the repository
2. Install dependencies:
   ```bash
   npm install
   ```

3. Create `.env` file in the root directory with your configuration:
   ```bash
   cp .env.example .env
   ```

4. Fill in the `.env` file with your values:
   - `DISCORD_TOKEN`: Your Discord bot token from [Discord Developer Portal](https://discord.com/developers/applications)
   - `DISCORD_CLIENT_ID`: Your Discord app ID
   - `DISCORD_GUILD_ID`: (Optional) Your Discord server ID for faster command registration
   - `DATABASE_URL`: PostgreSQL connection string

### Running the Bot

```bash
npm start
```

The bot will automatically:
- Create the database schema on first run
- Register slash commands to Discord
- Run cleanup tasks hourly

## Commands

All commands use the `/work` slash command with subcommands:

### `/work add`

Add a new work item. Status is automatically set to `todo` with 0% progress.

**Parameters:**
- `leadername` (required): Name of the team lead
- `workname` (required): Name of the work item
- `deadline` (required): Deadline for the work

**Usage:**
```
/work add leadername:John workname:ProjectX deadline:2026-06-30
```

**Result:**
- Creates a new work item owned by you
- Status: `todo`
- Progress: 0%

---

### `/work check`

View all work items you own. Shows a summary of each item.

**Parameters:**
- None (automatically uses your name)

**Usage:**
```
/work check
```

**Result:**
Shows an embed with all your work items:
- Work name
- Leader name
- Current status (todo/progress/done)
- Progress percentage
- Deadline

---

### `/work update`

Update the progress of a work item. Status is automatically derived from progress:
- 0% → `todo`
- 1-99% → `progress`
- 100% → `done`

**Parameters:**
- `workname` (required): Name of the work item to update
- `progress` (required): New progress percentage (0-100)

**Usage:**
```
/work update workname:ProjectX progress:50
```

**Result:**
- Updates progress and automatically changes status
- Only the work owner or server managers can update

**Permissions:**
- Work owner: ✓ Can update
- Leader: ✗ Cannot update
- Server manager: ✓ Can update
- Other team members: ✗ Cannot update

---

### `/leader export`

Export all work items you lead as a CSV file.

**Parameters:**
- None (automatically uses your leader name)

**Usage:**
```
/leader export
```

**Result:**
- Downloads a `.csv` file with your led work items
- Rows are sorted by `workowner`, then `workname`
- Columns: leader name, work owner, work name, deadline, status, progress

---

## Features

### Status Management
- **Progress-based status**: Status automatically changes based on progress percentage
  - 0% = `todo`
  - 1-99% = `progress`
  - 100% = `done`

### Per-Owner Work Names
- Different users can have work items with the same name
- Work names are unique per owner, not globally

### Leader Export
- Leaders can export every work item they lead as a CSV file
- Export output is sorted by `workowner`, then `workname`
- CSV omits internal database fields like `id`, `created_at`, and `updated_at`

### Automatic Cleanup
Work items are automatically deleted when:
- 7 days have passed since the item was marked as `done`, OR
- 30 days have passed since the item was last updated

The cleanup runs every hour in the background.

### Permissions
- **Adding**: Any user can add work items; they become the owner
- **Checking**: Users see only their own work items
- **Updating**: Only the work owner or server managers can update progress

## Database Schema

The bot automatically creates and maintains this schema:

```sql
CREATE TABLE public.work_items (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    leadername TEXT NOT NULL,
    workowner TEXT NOT NULL,
    workname TEXT NOT NULL,
    deadline TEXT NOT NULL,
    status TEXT NOT NULL CHECK (status IN ('todo', 'progress', 'done')),
    progress INTEGER NOT NULL DEFAULT 0 CHECK (progress >= 0 AND progress <= 100),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(workname, workowner)
);

CREATE INDEX work_items_owner_idx ON public.work_items (workowner);
```

## Troubleshooting

### "Missing DISCORD_TOKEN in the environment"
- Check that `.env` file exists and `DISCORD_TOKEN` is set
- Verify the token is valid in Discord Developer Portal

### "Missing DATABASE_URL in the environment"
- Check that `.env` file has `DATABASE_URL` set
- Verify the PostgreSQL connection string is valid

### "relation "public.work_items" does not exist"
- Database schema failed to create
- Check that `DATABASE_URL` points to a valid PostgreSQL database
- Ensure the user has permissions to create tables

### Commands not showing in Discord
- If `DISCORD_GUILD_ID` is set, commands take a few minutes to register
- If not set, commands are global and can take up to 1 hour to appear
- Try restarting the Discord client
